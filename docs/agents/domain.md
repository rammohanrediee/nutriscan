# Domain docs

Before exploring or changing the codebase:

- Read root `CONTEXT.md` when present.
- Read relevant ADRs under `docs/adr/` when present.
- Create glossary entries and ADRs lazily, only after a term or durable trade-off is resolved.
- Use canonical terms from `CONTEXT.md` in issues, specs, tests, and implementation.
- Surface conflicts with an existing ADR instead of silently overriding it.

Layout: single-context, with root `CONTEXT.md` and root `docs/adr/` created when the first ADR is
accepted.
